# 社内文書QA（RAG）デモ

社内規程・業務マニュアルに AI で答えさせるための、小さな実働デモです。

- 質問に対して、社内文書から根拠を探して答える
- **回答には必ず出典（ファイル名＋見出し）を付ける**
- **文書に書いていないことは「文書に記載がありません。」と答える**（推測で埋めない）
- 文書を更新したら、**変わった部分だけ**を再埋め込みする
- API キーが無くても `--dry-run` で動く（テストも外部 API なしで通る）

文書は架空の会社「株式会社ミナトテック」の規程 11 本（`docs/`）です。実在の企業・個人情報は含みません。

## 構成

```
docs/*.md ──ingest──▶ 見出し単位でチャンク分割 ──▶ 埋め込み ──▶ SQLite (data/index_*.db)
                      （長い節は分割・短い節は結合）  Gemini or 擬似     チャンクのハッシュで差分判定

質問 ──▶ ハイブリッド検索 ─────────▶ 上位5チャンク ──▶ Gemini（JSON出力）──▶ コードで検証
         ベクトル(コサイン) + BM25                      answerable / answer /        根拠番号が無効なら
         を RRF（逆順位融合）で合成                      source_ids                   「記載なし」に倒す
                                                                                    ──▶ 回答 + 出典
```

| ファイル | 役割 |
|---|---|
| `ragdemo/chunker.py` | 見出し単位の分割、長い節の分割、短い節の結合 |
| `ragdemo/ingest.py` / `store.py` | 取り込みと SQLite 保存。チャンク内容の SHA-256 で差分判定 |
| `ragdemo/embed.py` | `GeminiEmbedder`（`gemini-embedding-001`、768 次元）と `MockEmbedder`（文字バイグラムのハッシュ） |
| `ragdemo/search.py` | BM25（日本語は文字バイグラム）＋ベクトル検索を RRF で合成 |
| `ragdemo/answer.py` | 回答生成。プロンプトのルールと、コード側の出典付与・拒否判定 |
| `ragdemo/evaluate.py` | 評価。結果をキャッシュし、途中で止まっても再開できる |
| `ragdemo/cli.py` / `web.py` | CLI と、1 ページの Web UI（FastAPI） |

### 「捏造しない」ための仕組み
プロンプトのお願いだけに頼らず、コードでも縛っています。

1. モデルには JSON（`answerable` / `answer` / `source_ids`）で返させる。
2. `answerable=false`、回答が空、または `source_ids` が参考文書の番号として 1 つも有効でない場合は、答えがあるように見えても「文書に記載がありません。」に置き換える。
3. 出典は**モデルが書いた文字列ではなく**、有効な `source_ids` から引いた実際のファイル名・見出しをシステムが付ける（存在しない出典を作れない）。
4. JSON が壊れていたら答えを出さない側に倒す。

## セットアップ

Python 3.10 以上（動作確認は Python 3.14 / Windows）。

```
pip install -r requirements.txt
```

実 API を使う場合は、`GEMINI_API_KEY` を環境変数、またはこのフォルダの `.env`（`.env.example` をコピーして作る。git 管理外）に置きます。別の場所の `.env` を使うなら `GEMINI_ENV_FILE=<パス>` で指定します。キーの値はどこにも出力・保存しません。

## 使い方

```
python -m ragdemo ingest                 # docs/ を取り込む（2回目以降は変更分だけ）
python -m ragdemo ask "夏季休暇は何日取れますか？"
python -m ragdemo ask "..." --show-chunks # 検索で取れたチャンクとスコアも表示
python -m ragdemo serve --port 8000      # Web UI（http://127.0.0.1:8000）。--host は変えないでください
python -m ragdemo eval                   # eval/questions.jsonl で評価
```

**`--host` は既定の `127.0.0.1` のままにしてください。** Web UI の API には認証がなく、`0.0.0.0` などで LAN に公開すると、第三者があなたの Gemini の枠を使えてしまいます。

すべてのコマンドに `--dry-run` を付けると外部 API を使いません（擬似ベクトル＋検索結果の抜粋を返す。意味は理解しないので精度は低く、動作確認・テスト用です）。

実行例（実 API）:

```
$ python -m ragdemo ask "夏季休暇は何日取れますか？"
夏季休暇は7月から9月の間に3日間、有給で取得できます。

出典:
- leave.md「第6条 夏季休暇」

$ python -m ragdemo ask "社員食堂のランチの値段はいくらですか？"
文書に記載がありません。
```

### 文書を更新したとき
`docs/` のファイルを編集して `ingest` を再実行すると、内容が変わったチャンクだけが再埋め込みされます（`再埋め込み N・再利用 M・削除 K` と表示）。埋め込みモデルを変えたときだけ全件を作り直します。

### テスト
```
python -m pytest
```
外部 API なし（擬似埋め込み）で、チャンク分割・差分取り込み・検索・出典/拒否ルール・評価の中断再開・Web API を確認します。

## 評価

`eval/questions.jsonl` の 21 問（文書に答えがある単一文書 12 問、複数文書にまたがる 4 問、文書に答えが無い 5 問）に、期待する出典を付けています。`eval` コマンドで次を数えます。

**実 API（`gemini-3.5-flash-lite` ＋ `gemini-embedding-001`）、2026-10-04、21 問中 21 問を実行**

| 指標 | 結果 |
|---|---|
| 出典の一致率（期待した出典をすべて引用） | 14/16（88%） |
| 出典の一致率（期待した出典を 1 つ以上引用） | 15/16（94%） |
| 答えが無い質問で正しく拒否した率 | 5/5（100%） |
| 答えがあるのに拒否した率（誤拒否） | 1/16（6%） |
| 回答に必須キーワードが含まれた率（簡易な正確さ） | 15/16（94%） |
| 検索上位 5 件に期待出典がすべて入った率 | 15/16（94%） |

質問ごとの回答・引用元は `eval/results_2026-10-04.md`、生データは `eval/cache_gemini.jsonl` にあります。

失敗した 2 問:
- Q15（複数文書）: 検索が `security.md` 第5条を上位 5 件に拾えず、`equipment.md` だけを引用した。
- Q16（複数文書）: 検索は期待した 2 文書を拾っていたが、「どのシステムで精算するか」が `travel.md` には書かれておらず `expense.md` を経由する必要があるためか、モデルが「記載なし」と答えた（誤拒否）。

### 評価の限界（正直に）
- **文書は筆者が書いた架空のきれいな文書 11 本**（計 63 チャンク）です。実在の社内文書にある表記ゆれ・古い版・矛盾・表や図・長大な PDF などは含まず、**この数字をそのまま実運用の精度とは見なさないでください**。
- 質問 21 問は少なく、1 問で約 5 ポイント動きます。質問も文書と同じ人が作っているため、検索にとって易しい言い回しに偏っています。
- 「正確さ」は必須キーワードの含有という簡易判定です。意味として正しいか・言い過ぎていないかは人の目で見ていません（質問ごとの回答は結果ファイルで確認できます）。
- 拒否の判定は答えが無い 5 問だけです。「関連する記載はあるが答えは無い」型（Q19 育児休業中の給与、Q21 在宅勤務の電気代）は含めましたが、より巧妙な誘導質問や、文書内に紛れた指示文への耐性（プロンプトインジェクション）は評価していません。
- 実 API 評価は `temperature=0` で 1 回ずつ実行しただけで、繰り返しによるばらつきは測っていません。
- `--dry-run` の評価（擬似ベクトル＋抜粋）は動作確認用で、数字は意味を持ちません。

### 評価の再開
Gemini の無料枠はモデルごとに 1 日あたりの回数に上限があります。上限（429）に当たると評価はそこで止まり、**終わった分だけ**を集計してレポートに「N / 21 問」と明記します。質問ごとの回答・引用・検索結果・生成日は `eval/cache_gemini.jsonl` に保存されるので、後日 `eval` を再実行すれば続きから進みます。キャッシュは、質問文・生成モデル・埋め込みモデル・文書の内容・システムプロンプト・検索設定（TOP_K・RRF の k）のどれかが変わると無効になり、その質問は取り直します。出典一致やキーワード判定の結果は保存せず、毎回、保存済みの回答と期待出典から計算し直します。レポートには各結果の生成日を記載します（キャッシュを再利用しても、取得日は古いまま残ります）。`--limit N` で新規 API 呼び出しの回数を絞ることもできます。

## 既知の限界・今後
- 対応形式は Markdown のみ（PDF・Word・Excel の取り込みは未対応）。
- 日本語の BM25 は形態素解析ではなく文字バイグラムです（依存を増やさないため）。
- 会話の履歴や追質問には対応していません（1 問 1 答）。
- アクセス権（部署ごとに見せる文書を変える等）、認証、ログ保存は実装していません。
- チャンクは最大 500 文字・最小 40 文字（`ragdemo/config.py`）。文書の性質に合わせた調整は行っていません。
